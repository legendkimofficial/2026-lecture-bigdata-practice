# Task 3: PCY 구현과 메모리 실험

`bench.py`와 `PlainApriori`는 수정하지 않았다. seed 246, 장바구니 20,000개,
품목 2,000개, support 50의 동일 입력에서 빈발 쌍 6,397개와 각 support 값이
기준 구현의 딕셔너리와 정확히 같았다. 작은 무작위/경계 입력 207개에 버킷 수
1, 7, 64, 257을 적용한 828회 비교 및 재실행 초기화 검사도 통과했다.

## 버킷 크기와 필터 효과

| 버킷 수 | 정수 배열 객체 | bitmap 객체 | 빈발 버킷 | 최대 쌍 카운터 | 기준 대비 감소 |
|---:|---:|---:|---:|---:|---:|
| 기준 Apriori | 해당 없음 | 해당 없음 | 해당 없음 | 820,259 | — |
| 1,048,576 (기본값) | 4,194,384 B | 131,129 B | 6,981 | 13,357 | 98.37% |
| 65,536 | 262,224 B | 8,249 B | 21,574 | 313,855 | 61.74% |

기본 배열은 `array('I')`이며 이 환경에서 한 원소는 4 B이다. 실제 데이터
부분은 4,194,304 B이고 배열 객체 부가 비용은 80 B이다. `bytearray` bitmap은
버킷당 1 bit로 데이터 부분 131,072 B와 부가 비용 57 B를 사용한다.
버킷 누적값은 support에서 포화시켜도 빈발 여부 판단은 유지된다.

기본값은 해당 데이터에서 충돌로 통과하는 불필요한 쌍을 줄이면서 첫 패스의
배열 비용을 약 4 MiB로 제한한다. 버킷을 1/16로 줄이면 배열은 작아지지만
충돌이 늘어 빈발 버킷 필터를 통과하는 쌍과 카운터가 증가했다. 두 설정 모두
최종 딕셔너리는 동일하므로 충돌은 정확도보다 메모리 효율에 영향을 준다.

## 메모리의 동시 존재와 실제 전환점

bitmap 변환 중에는 정수 배열과 bitmap이 잠시 함께 존재하므로 두 객체만
합쳐 4,325,513 B가 필요하다. 여기에 품목 ID, 품목 support, 빈발 품목 집합
등의 비용도 있다. 배열과 품목 support 목록은 두 번째 패스의 쌍 딕셔너리를
만들기 전에 삭제한다. 결과 생성 시에는 기존 카운터에서 `popitem()`으로
꺼낸 뒤 결과에 넣어 두 support 딕셔너리의 엔트리 수를 중복해서 유지하지
않는다. 객체와 딕셔너리의 실제 할당 비용은 아래 측정에 포함된다.

각 행은 동일한 seed 입력의 **앞 N개 장바구니**, support 50, 기본 버킷 수를
사용했다. 입력과 정답 딕셔너리를 먼저 만든 뒤 GC를 수행하고, 각 알고리즘을
독립된 `tracemalloc` 시작/종료 구간에서 순차 실행했다.

| 장바구니 수 N | 기준 최대 카운터 | PCY 최대 카운터 | 기준 traced peak (B) | PCY traced peak (B) |
|---:|---:|---:|---:|---:|
| 1,000 | 1,078 | 60 | 190,884 | 4,484,661 |
| 2,000 | 6,228 | 182 | 834,044 | 4,493,617 |
| 3,000 | 16,388 | 373 | 1,695,892 | 4,495,317 |
| 5,000 | 50,168 | 882 | 6,491,324 | 4,524,149 |
| 20,000 | 820,259 | 13,357 | 102,288,652 | 4,667,833 |

전체 입력에서 추가 Python 할당의 peak는 약 97.55 MiB에서 4.45 MiB로
95.44% 줄었다. 그러나 N=3,000에서는 PCY가 더 많은 메모리를 사용하고
N=5,000에서는 더 적게 사용했다. 따라서 이 입력 계열의 전환점은 대략
3,000~5,000개 사이이다. 정확한 경계를 탐색한 결과는 아니다. support,
품목 수, 장바구니 길이, 데이터 분포, 해시 충돌, Python 딕셔너리 비용이
달라지면 전환점도 달라진다. 작은 입력에서는 고정 배열 비용이 이득을 넘는다.

이 수치는 알고리즘 실행 중 새로 추적한 Python 할당과 반환 결과를 포함하고,
미리 생성한 입력 및 비교용 정답은 제외한다. 프로세스 전체 RSS가 아니며,
쌍 카운터 수의 감소율과 byte 단위 메모리 감소율도 서로 다르다.

## 실행 시간과 재현

추적하지 않은 버킷 실험은 기준 1.75초, 기본 PCY 2.49초, 작은 버킷 PCY
2.95초였다. 전체 입력의 `tracemalloc` 측정 구간에서는 각각 기준 5.22초와
기본 PCY 50.51초가 걸렸다. 정수 연산을 추적하는 비용과 시스템의 다른 작업
때문에 이 시간들을 직접 비교해 알고리즘 속도 차이로 해석하면 안 된다.
과제의 평가 지표는 최대 쌍 카운터 수이다.

`w06-apriori` 디렉터리에서 다음 명령으로 정답 검증, 두 버킷 실험, 순차적인
메모리 측정을 재실행하고 `out/pcy_experiments.json`을 생성할 수 있다.
시간과 byte 수는 Python 버전 및 실행 환경에 따라 조금 달라질 수 있다.

```bash
python3 measure_pcy.py
python3 bench.py --yours
```
