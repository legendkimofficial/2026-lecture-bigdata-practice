- 실행일: 2026-10-13 (한국 시간 기준 같은 날짜)
- CPU: AMD Ryzen 7 9800X3D 8-Core Processor / 논리 CPU 16개
- RAM: 운영체제에서 확인한 물리 메모리 31.15 GiB; 측정 시작 시 사용 가능 11.24 GiB
- OS: Windows-11-10.0.26300-SP0 / Python 3.13.15
- ChatGPT Codex가 연결된 Windows 실행 환경에서 직접 실행했다. 다른 사용자 앱의 실행 상태는 확인하지 못했으므로, 유휴 상태의 전용 벤치마크라고 가정하지 않는다. 측정 중 다른 과제 벤치마크를 동시에 실행하지 않았다.
- 문서당 초기 shingle 60개, 어휘 5,000개, seed 246, 임계값 0.6, 전체의 약 120/2120을 유사 문서로 생성했다. 모든 n에서 실제 문서 수가 요청값과 같고, 전수 비교 호출 수가 n(n−1)/2인지 검사했다.
- LSH는 해시 120개, 밴드 30개, 밴드당 4행이다. 최종 유사도는 제공된 Counter로 계산한다.
- 각 크기에서 1회 측정했다. 두 방법 모두 tracemalloc을 켠 상태의 perf_counter 경과 시간이다. 입력 생성 시간과 입력 문서 메모리는 제외하고, find() 내부의 전처리·서명 생성·후보 생성·검증은 포함한다.
- 제공 코드의 bench.build()[:n]은 최대 2,120개만 만들므로, Task 2에서 같은 생성 모형으로 정확히 n개를 만드는 함수를 사용했다. bench.py와 공식 test_tasks.py는 원본 그대로다.
- 기본 실험은 7개 크기, 125~8,000개로 64배 범위를 측정했다. 교차점 부근은 추가 측정했다.

## 이차 증가 확인 (A4)

| 문서 수 변화 | 전수 비교 시간 배율 | 이론상 비교 횟수 배율 |
|---|---:|---:|
| 125 → 250 | 3.837배 | 4.016배 |
| 250 → 500 | 4.208배 | 4.008배 |
| 500 → 1,000 | 4.085배 | 4.004배 |
| 1,000 → 2,000 | 4.059배 | 4.002배 |
| 2,000 → 4,000 | 4.005배 | 4.001배 |
| 4,000 → 8,000 | 4.218배 | 4.001배 |

실제 시간 배율은 3.837~4.218배로 4배에 가깝다. 같은 크기의 shingle 집합에서 비교당 비용이 거의 일정하여, n(n−1)/2번 비교하는 전수 탐색의 이차 증가와 부합한다. 작은 구간의 오차에는 한 번씩만 측정한 점과 백그라운드 부하가 영향을 줄 수 있다.

## 교차점과 작은 입력에서의 손해 (A7, A8)

측정한 크기 중 LSH가 처음 빨라진 값은 **n=750**이다. n=625에서는 전수 비교 0.8334s, LSH 0.9739s이고, n=750에서는 각각 1.2012s, 1.0027s였다. 따라서 이번 측정에서 교차 구간은 **625~750개 사이**다. 반복 실험으로 확정한 단일 임계 n은 아니다.

LSH는 실제 비교를 시작하기 전에 shingle을 행 번호로 변환하고, 행별 열 목록을 만들고, 120개 해시로 최소값 서명을 갱신한 다음 30개 밴드 버킷과 후보 집합을 구성한다. 작은 입력에서는 이 전처리 비용이 절약한 전수 비교 시간보다 크다. 데이터가 커지면 전수 비교의 이차 증가가 이 비용을 추월한다. 후보가 과도하게 충돌하는 데이터에서는 LSH도 후보 수와 메모리가 이차적으로 늘어날 수 있으므로 항상 선형이라고 볼 수는 없다.

## 가장 큰 입력의 메모리와 중단 지점 (A2, A5)

n=8,000에서 전수 비교는 **147.37초**, LSH는 **3.84초**였다. 전수 비교가 미리 정한 60초 대기 기준을 넘었으므로 이 크기를 불편해진 지점으로 기록하고, 두 방법의 해당 크기 측정을 끝낸 뒤 확대를 멈췄다. 먼저 부담이 된 것은 **시간**이며, 메모리 부족이나 OOM은 관찰하지 않았다.

| 방법 | find()의 추가 peak 할당(bytes) | MiB |
|---|---:|---:|
| 전수 비교 | 68,232 | 0.0651 |
| LSH | 33,288,472 | 31.7464 |

이 값은 tracemalloc으로 추적한 find() 내부 Python 할당의 peak다. 이미 생성한 입력 집합, Python 인터프리터와 프로세스 전체 RSS는 포함하지 않는다. 전수 비교는 모든 쌍을 저장하지 않고 순회하므로 추가 메모리가 작고, LSH는 행 인덱스·서명·버킷을 저장하므로 추가 메모리를 더 사용한다. 서로 다른 실행의 bench.txt는 tracemalloc 없이 측정하므로 여기의 시간과 직접 혼합하지 않는다.
